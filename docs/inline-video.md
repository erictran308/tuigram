# Inline-воспроизведение кружков (video notes): статус

Рабочие заметки нашего форка. Продолжать можно с любой машины: весь код в
`main`, здесь — контекст, который не виден из коммитов.

## Симптом (найдена причина, фикс в `visible_rows`)

При воспроизведении кружка по Space (inline, в чате) кадр **обрезан снизу
прямой линией**, левый верх на месте. При этом:

- масштабирование medium (2x) работает — пузырь расширяется как надо;
- после окончания воспроизведения превью (thumbnail) — идеальный круг;
- полноэкранный плеер (Enter) работает всегда.

## Причина (2026-11-25)

Ошибка в `draw_photos` (src/ui/messages.rs): высота ректа плейсхолдер-ячеек
считалась как `min(slot.rows, area.height) - max(0, y)` — смещение слота `y`
вычиталось даже когда ничего не проскроллено. Слот из 20 строк, начинающийся
на строке 8, получал только 12 строк ячеек; kitty раскладывал кадр по
`c×r = cols×rows` полного слота, а нижним 8 строкам сетки не на чем было
отобразиться → срез низа кружка, растущий с ростом `y`. Скриншот
`2026-11-24-171313.png` (y≈8, срезано ~40%) подтверждает расчёт.

Фикс: чистая функция `visible_rows` = пересечение отрезка слота с панелью,
`shown = min(y + rows, height) - max(0, y)`, плюс юнит-тест
`an_inline_players_visible_rows_cover_the_whole_slot`. Плейсмент по-прежнему
объявляется на полный слот (`player.placement = Some((slot.cols, slot.rows))`)
— ячейки вне экрана просто не показывают свои куски, это корректный скролл.

## Открытые вопросы, если срез где-то останется

1. kitty вписывает кадр в `c×r` с сохранением пропорций (contain). Если бокс
   слота не квадратный в пикселях (рассинхрон `images.font_size()` и
   реальной геометрии ячейки kitty), будут поля по бокам/сверху — не срез,
   но «кружок не на весь бокс». Замерить фактический размер ячейки:
   `kitten @ ls` / query через `\x1b[16t` против ratatui-image.
2. Попробовать отдельный плейсмент: `a=p,U=1,i=…,c=…,r=…` после `a=t`
   (передача без отображения), как рекомендуют доки kitty.

## ВАЖНО: как НЕ тестировать

Нельзя запускать второй экземпляр tuigram на **копии** живой TDLib-базы
(`TG_DATA_DIR=/tmp/copy`): копия = та же сессия с тем же auth-ключом.
Telegram отвечает `406 AUTH_KEY_DUPLICATED` и **насовсем отзывает ключ** —
сессия умирает, нужен перелогин (уже словили 2026-11-24). Для живых тестов:
основной клиент + скриншоты, либо отдельный тестовый аккаунт Telegram.
